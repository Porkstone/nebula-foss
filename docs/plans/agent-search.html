NEBULA / IMPLEMENTATION PLAN

Make the directory easy for agents to search.

Assumption: “agents” means AI browsing and coding agents. Production currently sends an empty app shell to clients without JavaScript, and search/filter state exists only inside React.

Public, predictable access

  1. Add a read-only GET JSON API at /api/v1/projects, backed by the same indexed search and licence policy as the website. Support keyword, category, contribution and maintenance filters, sorting and bounded cursor pagination.
  2. Return only public project details, repository URLs and explicit next-page links. Exclude account identifiers and operational metadata. No account, token or JavaScript required.
  3. Publish /llms.txt, an OpenAPI document, and a linked “For agents” guide with working examples, filter values, pagination and search limitations.

Browser search

Keep search and filters in URL parameters so agents can navigate directly, people can share searches, and browser back/forward restores them. Clearly show relevance ordering during text search. Preserve the existing design and accessible search label.

Verification and delivery

Test anonymous HTTP access, filters, pagination, invalid input, hidden and unsupported licences, public-field boundaries, and URL round trips. Run typecheck, tests, build and lint. Push to master under the existing authorization; Vercel deploys the frontend and Convex together to production careful-wombat-946. Verify the live API, discovery documents and browser URL behavior using public read-only requests. No development backend or production test records.

Questions

No blocking questions. This adds ways to discover the existing directory; it does not promise semantic search, typo correction, or access to unlisted GitHub repositories.
