NEBULA / IMPLEMENTATION PLAN

Create an account and sign in with Google

Add Google OAuth to the existing Convex Auth integration. A first Google sign-in creates an account; later sign-ins use that Google account. Preserve email/password authentication and existing project ownership.

Implementation

  1. Register the Auth.js Google provider alongside the existing Password provider. Keep the existing auth tables, JWT configuration, and HTTP callback routes.
  2. Add a keyboard-accessible “Continue with Google” button to both account creation and sign-in. Show progress, prevent competing submissions, and report initiation failures. Let Convex Auth handle the OAuth redirect and session exchange.
  3. Document Google Cloud configuration, the deployment-specific callback URL, server-only credentials, and production setup.

Verification

Run TypeScript checks, existing tests, lint, and the production build. Push to the existing development deployment and inspect both authentication screens in the browser. Complete a real Google round trip once the OAuth client is configured.

Configuration dependency

The development deployment is fearless-crow-586. Google credentials are not configured. Its authorized redirect URI is https://fearless-crow-586.convex.site/api/auth/callback/google. Configure AUTH_GOOGLE_ID and AUTH_GOOGLE_SECRET in the Convex dashboard. Existing signing keys must stay in place.

Questions

No product clarification is needed. A Google OAuth client must be configured before a real account can complete sign-in.
