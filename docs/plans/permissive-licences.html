NEBULA / IMPLEMENTATION PLAN

Open code, with room to build.

Only showcase repositories whose GitHub-detected licence is MIT or one of the ten licences supplied by the site owner. Enforce the policy on the server and explain it before submission.

One permitted set

MIT, Unlicense, CC0-1.0, 0BSD, MIT-0, WTFPL, ISC, BSD-2-Clause, BSD-3-Clause, Zlib, BSL-1.0

MIT is included as the requested baseline and recommended option. Apache-2.0 is removed because it is outside the specified list. Unknown, missing, custom, and unsupported licence identifiers are rejected.

Implementation

  1. Share the exact allowlist across validation and the interface. Reject unsupported repository submissions with a clear explanation and an MIT recommendation. Keep private-repository errors distinct.
  2. Enforce the same rule when storing and refreshing listings. Exclude older ineligible listings from browsing and search immediately, retain them in the owner's management view with an explanation, and bypass cached checks for ineligible stored licences.
  3. Add a public /licences page with a focused editorial layout matching Nebula's themes. Explain the policy, recommend MIT, list every permitted licence with a source link, and explain how repository checks work.
  4. Link the page from navigation, the footer, the mission dialog, and submission guidance. Add React Router and a Vercel rewrite so direct links and browser history work.

Verification

Test every accepted identifier, missing/unsupported licences, submission rejection without persistence, legacy listing visibility, and refresh behaviour. Run typecheck, tests, lint, and build. Push the backend to personal development deployment fearless-crow-586 and inspect desktop/mobile page navigation and submission feedback.

Clarifications

No clarification is required to proceed. This list is Nebula's editorial eligibility policy; the page will describe licence differences without claiming that their legal terms are identical.
