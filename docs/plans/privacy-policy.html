NEBULA / IMPLEMENTATION PLAN

A privacy policy grounded in the app.

Add a public /privacy page that explains Nebula's current data practices in plain language, using the existing editorial page style and light/dark themes.

Evidence

The database stores account/profile details, authentication/session records, and project listings linked to their submitter. Google sign-in requests basic identity scopes. GitHub repository metadata is checked server-side. The frontend stores authentication data and a theme preference locally. Convex provides the backend; Vercel hosts the deployed frontend. No optional analytics or advertising integration is present in the repository.

Implementation

  1. Explain collected data, purposes, public listing fields, Google permissions, browser storage, service providers, retention criteria, privacy rights, and contact details. Avoid promising automatic account deletion or fixed retention periods that do not exist.
  2. Add the policy route and page metadata. Link it from every footer and from the account creation/sign-in dialog before information is submitted.
  3. Keep the privacy page accessible without authentication. Document its production URL for the Google OAuth branding settings.

Validation

Run the production build and lint; inspect the direct route, navigation, sign-in link, page headings, and mobile/desktop layouts. Preserve the unrelated, locally generated logo assets.
