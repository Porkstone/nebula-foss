NEBULA / BUILD PLAN / 23 SEPTEMBER 2026

A home for useful,
open-source projects.

Build on the existing Vite / React / TypeScript scaffold with a Convex database, Convex Auth, Tailwind, and Lucide icons. The interface uses warm paper, ink typography, and vermilion accents.

Experience

  1. Explore public projects, search descriptions, filter categories, maintenance and contribution status, and sort by stars or newest.
  2. Register and sign in with Convex Auth. The installed stable package has no passkey provider, so use email/password and explicitly document the limitation.
  3. Submit a GitHub URL, category, original description, and contribution/maintenance preferences. Validate public visibility and a permissive license on the server.
  4. Manage only your own listings: edit descriptions/status and remove listings.

Data and automation

Store GitHub repository ID, canonical name, license, stars, forks, language, archived status, pushed date, ETag, and refresh health separately from user-authored information. Use a daily cron with bounded, serial scheduled batches, conditional requests and rate-limit backoff. Hide unavailable/private or no-longer-eligible repositories and surface the reason to the submitter.

License policy

Accept MIT, Apache-2.0, BSD-2-Clause, BSD-3-Clause, ISC, 0BSD, Unlicense and CC0-1.0. These are an explicit product allowlist of permissive licenses, not a claim that their legal terms are identical. Unknown, custom and copyleft licenses are rejected.

Verification

Compile frontend/backend, deploy to the existing personal development deployment, test authorization, license rejection, duplicate submissions and refresh behavior, and exercise registration and submission in a browser.

GitHub research

Daily repository metadata polling is supported by the repository API, subject to API terms and rate limits. Use conditional requests, respect Retry-After and reset headers, and avoid concurrent polling. A server-side GitHub token raises the unauthenticated allowance.

Deployment

Development target: fearless-crow-586. Configure auth signing keys and SITE_URL there. Provide a Vercel build command that deploys Convex and injects the frontend URL; production requires a Convex deploy key in Vercel.

Open questions

No blocking questions. Passkeys would require an authentication-provider change or a separately audited WebAuthn integration.
